# 디자인 품질 기준 (impeccable 핵심 요약 — 상세페이지용)

목차: 0. 연출 언어 — 연출형 기본 · 1. 만들기 전에 정하는 것 (30초) · 2. 타이포 (글자) · 3. 레이아웃 (배치·여백) · 4. 색 · 5. 깊이·면·디테일 · 6. 모션 — 기본으로 2곳, 그 이상 금지 · 7. 카피(UX 문구) · 8. 만든 뒤 점검 (한 번에, 한 번만) · 9. 템플릿별 디자인 규칙 · impeccable 연동 (설치돼 있을 때)

impeccable 스킬(Apache 2.0)에서 상세페이지에 필요한 규칙만 뽑아 한국어로 옮겼다.
**impeccable 스킬이 설치돼 있으면** 이 파일 대신 그 스킬을 직접 쓴다 (맨 아래 "impeccable 연동" 참고). 없으면 이 파일이 기준이다.

상세페이지는 impeccable 기준으로 **Persuade(설득) 모드**다 — 손님이 결정하고 행동하게 만드는 게 목적. 디자인이 곧 상품이다. 그러니 "안전하게"가 아니라 "분명하게". 다만 손님은 폰으로 엄지로 넘기며 본다는 걸 잊지 말 것.

## 0. 연출 언어 — 모든 카테고리 기본 (2026-11-04 사용자 지시)

> 2026-11-20: 템플릿이 3종이 됐다. 아래 0항은 **연출형(`template.html`)의 언어**다. 정보설득형(`template-spec.html`)은 선으로 그은 목록·비교·부위 짚기, 매거진형(`template-magazine.html`)은 풀블리드↔비켜 놓은 사진과 여백이 각자의 연출 언어다. 공통으로 지키는 건 "네모 크롭 사진 위 단조로운 글씨 금지"와 1~8항이다. 어떤 템플릿을 고를지는 SKILL.md "템플릿 고르기".

사용자 피드백: "네모난 크롭 이미지 위에 단조로운 글씨만 있다", "공감 섹션 딤이 제품 분위기에 안 맞게 어둡다". 레퍼런스(시리얼 상세페이지)는 **질감 바탕 위 누끼 소품 + 모양 있는 면 + 굵고 큰 글씨**였다. 그래서 아래가 기본이고, 아래 3·4항의 사진 블록 규칙보다 우선한다.

1. **질감 바탕(`.tex`).** 섹션 바탕에 상품 세계의 재질을 깐다 — 회벽·종이·린넨·나무결·콘크리트 등. 2종을 섹션마다 번갈아. 민무늬 단색 바탕만 이어지면 안 된다.
2. **누끼 소품 연출(`.scene`).** 첫 화면·해결·마무리는 사진 한 장 대신 누끼(상품·그릇·재료·소품)를 질감 위에 배치한다. 주인공 하나를 크게, 소품 2~4개를 화면 밖으로 살짝 걸치게, 살짝 회전. 그림자는 `drop-shadow`로 부드럽게.
   - **단, 첫 화면(s-01)은 예외 — 주인공 상품 누끼 하나만 둔다 (2026-11-07).** 첫 화면에 곁다리 소품을 깔면 "뭘 파는지"가 흐려진다. 상품을 가운데에 잘리지 않는 최대 크기로(`--y + 1.5 × --w ≤ 99`), 나머지는 질감 바탕과 글씨로만. 소품 2~4개를 쓰는 연출은 해결·사용 장면·마무리 섹션에서 한다.
3. **네모 크롭 사진을 맨몸으로 두지 않는다.** 사진이 필요하면 틀을 씌운다 — 아치(`.arch`), 원(`.circ`), 큰 둥근 모서리(`.soft`). 같은 급 정보는 우표 카드(`.stamp` + `.feat`), 숫자·인증은 인장 배지(`.seals`), 단계는 동그라미 줄(`.dots`), 제품 부위는 점선 짚기(`.mark`).
4. **글씨는 크고 굵게, 굵기 대비로 리듬.** 제목은 700~800, 앞부분만 가는 글씨(`.lt` 300)로 섞는다("<가는>이 한 그릇이 <굵은>좋은 이유"). 상품명·브랜드는 강조색 밑줄(`.u`). 손글씨풍 단일 굵기 폰트를 제목에 쓰지 않는다. 굵기가 하나뿐인 Jalnan(`data-font="bold"`, living 프리셋)은 1·4·11번 큰 제목에만 — 나머지 h2는 본문 폰트 800, `.lt`는 자동으로 본문 폰트 300이 된다(`presets.css`·`fonts.css`). 진한 색(검정·진갈색·남색)으로 밝은 질감 위에 — 대비가 곧 가독성.
5. **공감도 밝게.** 어두운 딤·스크림 금지. 밝은 생활 사진을 원형 틀에 넣고 말풍선(`.bubble`)에 고민 문구(`.ask`). 답답함은 문구로 표현하지, 화면 톤으로 하지 않는다.
6. **템플릿 기본 블록이 이미 이 방식이다** (`template.html` s-01 `.scene`, s-02 `.seals`, s-03 `.ask`, s-05 `.stamp`). 재료(누끼·질감) 만드는 법은 `image-guide.md` "누끼 소품 세트"·"질감 바탕".

## 1. 만들기 전에 정하는 것 (30초)

HTML 손대기 전에 세 줄로 적는다. 안 적으면 템플릿 기본값에 끌려간다.

- **세계관 한 줄:** Q9 분위기 + 상품 성격 → 예: "제주 농가 아침 햇살, 리넨과 나무, 손글씨 느낌 없이 정갈하게"
- **주인공:** 첫 화면에서 뭐가 제일 커야 하나 (상품 사진? 숫자? 한 줄 문장?)
- **색 하나:** 강조색은 한 가지. 구매 버튼·핵심 숫자·체크 표시에만 쓴다. 여기저기 뿌리면 힘이 없어진다.

## 2. 타이포 (글자)

- **폰트:** 기본은 Pretendard 하나(`data-font` 프리셋을 고르면 `fonts.css`의 그 블록 — 제목·본문 두 개까지). CDN 로드(`template.html`에 포함). 시스템 기본 폰트(맑은 고딕·Arial)가 표시용으로 보이면 실패.
- **역할 4개만:** 큰 제목 / 소제목 / 본문 / 보조(작은 회색). 역할마다 크기·굵기 차이가 **한눈에** 보여야 한다. 비슷비슷하면 계층이 없는 것.
  - 크기는 **페이지 폭에 비례(`cqw`)** — 템플릿 `--fs-*` 변수. 폰(430px)=최소, 860px=최대. 고정 px로 되돌리지 않는다 (PC 미리보기와 폰 캡처가 같은 비율이어야 한다).
  - 큰 제목 32→68px / `--display-weight` / 자간 -0.025em / 줄높이 1.22
  - 소제목 25→50px, 소소제목 19→38px / 줄높이 1.3~1.35
  - 본문 16→28px / 400 / 줄높이 1.65 — **본문·설명·표 내용은 430폭에서 16px 아래로 절대 안 내려간다** (폰 가독성)
  - 보조 14→24px, 각주·캡션 12→20px / 회색이되 대비 4.5:1 이상
  - **보조 글자 예외(2026-11-21):** 각주 `.fn`, 사진 캡션 `.cap`, 태그·라벨·알약, 브랜드바, 표 머리는 430폭에서 **12px 이상**이면 된다(대비 4.5:1 유지). 12px 미만은 어디에도 없다.
- **폰에서도 위계 유지:** 모바일에서 큰 제목과 소제목 크기 차이를 10px 이상 벌린다 (예: h2 32 / h3 22). 비슷하면 섹션 제목과 소제목이 구분되지 않는다.
- **자간:** 제목 -0.02~-0.03em. -0.04em 넘기면 뭉친다. 본문은 0.
- **한 줄 길이:** 본문 한 줄에 글자 22~32자(한글 기준). 860px에서 좌우 패딩 32px이면 자연히 맞는다.
- **제목 줄바꿈:** `word-break: keep-all` + `text-wrap: balance`. 한글 단어 중간이 잘리면 싸구려로 보인다.
- **숫자:** 가격·수치는 `font-variant-numeric: tabular-nums`로 자릿수 정렬.
- 긴 제목(2줄)·긴 가격·긴 후기 넣어서 **실제 문구로 깨지는지** 확인. 샘플 텍스트로만 보면 안 된다.

## 3. 레이아웃 (배치·여백)

- **눈 가늘게 뜨고 보기(squint test):** 흐리게 봐도 ① 주인공 ② 두 번째 ③ 그룹들이 순서대로 보여야 한다. 전부 같은 무게면 아무것도 안 보이는 것.
- **가까운 건 붙이고, 다른 건 떼기.** 제목-본문은 8~12px, 섹션-섹션은 56~72px. 여백이 전부 똑같으면 리듬이 없다. **제목 위 여백 > 제목 아래 여백.**
- **4px 단위 스케일:** 4·8·12·16·24·32·48·64·96. 이 밖의 값(13px, 27px…)은 쓰지 않는다.
- **섹션 배경 교차:** 흰 → 연한 → 흰 → 연한. 섹션 경계는 배경색으로 구분하는 게 기본. 구분선은 섹션 "안"의 호흡용이다(아래 참고).
- **이미지 블록으로 비율에 리듬을 준다.** `template.html`의 블록 9종(`hero` 4:5 / `wide` 4:3 / `split` 3:4+글 / `pair` 1:1×2 / `mosaic` / `lineup` / `stack` / `imgtext` 16:10)을 섹션마다 골라 쓴다. 카테고리별 정답은 `layout-refs.md`. **단독 이미지는 1:1이 아니다** — 1:1은 2장 이상 나열할 때만. 같은 비율 세 번 연속 금지. (2026-10-29 쿠팡·컬리·무신사 15개 상위 페이지 조사: 전부 가로↔세로↔2열이 번갈아 나온다.)
- **글은 위, 사진은 아래.** 블록 하나의 단위는 "제목 → 설명 2줄 → 이미지". 오버레이(`.imgtext`)는 공감 섹션 + 배너 1곳까지. 글↔사진을 좌우로 붙이는 `.split`은 기능 설명(가전·주방)에서 교차로 쓴다.
- **단독 이미지는 풀블리드가 기본.** 섹션(`.s`)엔 좌우 여백이 없고 글(`.tx`)과 그리드가 각자 여백을 가지므로, `hero`·`wide`·`imgtext`는 자연히 페이지 폭을 꽉 채우고 모서리 0. 여백 안에 두고 싶으면 `.inset`. 2열 그리드(`pair`·`lineup`·`mosaic`)는 여백 안. 글자(제목·본문·캡션)는 절대 풀블리드하지 않는다.
- **강조선(`.divider`)은 가운데 정렬 섹션의 제목 아래에만, 키워드 바(`.kw`)는 첫 화면 아래 1곳.** 페이지 전체에서 합쳐 **최소 3곳, 최대 5곳**. 모든 섹션에 넣으면 리듬이 아니라 창살이 된다.
- **제목 위 키워드 라벨(`.eb`)은 쓰지 않는다 (2026-11-20, impeccable craft-floor 금지 항목).** 예전엔 "이런 고민"·"01 · 키워드" 같은 이정표를 제목 위에 얹었지만, 제목이 제 무게로 서야 한다. "지금 어느 파트인지"는 ① 제목 앞부분 가는 글씨(`.lt`)로 맥락을 주고("<가는>그래서 <굵은>이렇게 만들었어요") ② 섹션 바탕색 교차로 경계를 보여준다. 영문 대문자 라벨("POINT", "FEATURE")도 금지 — 브랜드명만 영문 허용. 번호("01 / 02")는 조리·설치 순서처럼 순서 자체가 정보일 때 `.steps`·`.dots` 안에서만.
  - **예외 하나 — 매거진형 표지 키워드 줄(`.tags`, 2026-11-21).** `template-magazine.html` 표지(s-01) 두 톤 머리 줄(`.duo-head`)에만, 페이지당 1곳, `#` 2~3개. 제목 바로 위가 아니라 사진을 사이에 둔 지면 코너 문구라 눈썹 라벨이 아니다. 구체적인 말(용도·소재·장면: `#가방 속 정리` `#코듀로이`)일 때만 쓰고, `#TRENDY`·`#BEST`·`#감성` 같은 빈말이 되면 통째로 지운다. 섹션 제목 위·다른 템플릿에는 쓰지 않는다.
  - 같은 표지의 영문은 두 가지만 허용: 알약 배지(`.pill`)의 사실 하나("6 COLOR", "3P SET")와 h1 아래 영문 부제(`.en`, 상품명의 영문 표기). 둘 다 라벨이 아니라 정보다.
- **정보 블록으로 호흡을 준다.** 사진 5장 연속은 카탈로그다. 사이에 `.icons`(호환·재질 2~4개, 인라인 SVG), `.steps`(조리·설치 1-2-3), `.pills`(스펙 알약), `.callout`(다이어그램 설명), `.summary`(표)를 끼운다.
- **숫자 주장엔 각주(`.fn`).** "1위·누적 ○만·테스트 완료" 아래에 `* 기간 · 기관 · 기준`. 각주 없는 1위는 표시광고법 위반이고, 손님도 안 믿는다.
- **카드 남발 금지.** 아이콘+제목+텍스트 똑같은 카드 3개 나열은 게으른 구조. 카드 안에 카드는 항상 틀렸다. 기본 그림자는 없음(플랫) — 카드류(`.badge .review .qa`)는 1px 선, 프리셋(baby·toy)만 그림자.
- **터치 영역:** 버튼 높이 48px 이상. 링크·FAQ 펼침도 44px 이상.
- **이미지 비율 고정:** `aspect-ratio` 지정해서 로딩 중 레이아웃이 튀지 않게.

### 이미지 위 텍스트 (오버레이 합성)

"이미지 넣고 그 아래 캡션" 패턴은 페이지만 길어지고 기획안처럼 보인다. 그렇다고 사진마다 글을 얹지는 않는다 — **0항 연출 언어가 먼저**고, 오버레이(`.imgtext`)는 페이지당 1~2곳(와이드 배너·히어로)까지. 공감(3번)은 오버레이가 아니라 `.ask`(밝은 원형 사진 + 말풍선)가 기본이다.

- **스크림은 최후 수단:** 글자는 사진 위보다 질감 바탕·빈 공간 위에 둔다(0항). 사진 위에 꼭 얹어야 하면 밝은 사진 + `.light`(옅은 크림 그라데이션 위 진한 글자)를 먼저 쓰고, 어두운 스크림은 다크 테마(스포츠 등)에서만. 대비 4.5:1은 계산해서 확인.
- **공감 섹션은 어둡게 깔지 않는다 (2026-11-04).** 밝은 사진 원형 틀 + 말풍선(`.ask`). 문제 문구가 또렷이 읽히는 게 목적이고, 답답함은 문구가 만든다.
- **글자에도 좌우 패딩 32px 유지.** 이미지는 풀블리드여도 텍스트가 화면 끝에 붙으면 안 된다("글자는 풀블리드하지 않는다" 규칙은 오버레이에도 적용).
- **이미지 위엔 헤드라인 + 한 줄까지만.** 본문 문단을 사진 위에 올리지 않는다 — 긴 설명은 이미지 밖 본문으로.
- **텍스트 위치는 이미지의 빈 공간에 맞춘다.** 생성 단계에서 카피 공간을 미리 확보하는 게 우선이고(`image-guide.md` 원칙 4), 피사체 위를 글자가 가리면 `.bottom`으로 내리거나 이미지를 다시 뽑는다.
- **예외:** 히어로·비주얼 배너(페이지당 1~2개)는 텍스트까지 이미지에 디자인 가능 — `categories.md` 히어로 배너 가이드를 따른다.

## 4. 색

- **역할로 정한다, 색깔 모음이 아니라:** 바탕 / 올라온 면(연한 배경) / 본문 글자 / 보조 글자 / 강조(액션) / 구분선. 이 6개면 끝.
- **강조색은 희소해야 힘이 있다.** 버튼·핵심 숫자·체크·강조 한 단어. 섹션 제목 전체를 강조색으로 칠하지 않는다.
- **대비:** 본문 4.5:1, 큰 글씨 3:1, 버튼·아이콘 3:1. 눈대중 말고 계산 (`#6b7280` on `#fff` = 4.8:1 OK / `#9ca3af` = 2.9:1 본문 불가).
- **색 있는 면 위의 보조 글자**는 회색 말고 그 면의 색조를 띤 색으로. (어두운 남색 바탕 위 보조 글자 = 연한 남색, 회색 X)
- **그라데이션 글자 금지.** 강조는 굵기나 크기로.
- **다크 테마(고급)는 라이트를 뒤집는 게 아니다.** 어두운 바탕에서 글자는 줄높이 +0.05, 자간 +0.01em, 굵기 한 단계 올린다. 그림자는 안 보이니 면 밝기 차이로 깊이를 만든다.
- 어두운 테마를 "고급스러우니까"로 고르지 말 것. 손님이 어디서 보는가로 고른다 (낮에 폰으로 → 라이트가 기본). 카테고리 프리셋(`design-presets.md`)의 밝기도 출발점일 뿐이다 — impeccable 원칙 "밝기는 카테고리가 아니라 사용 장면으로".

## 5. 깊이·면·디테일

- **그림자는 offset + 부드러운 blur.** `0 4px 16px rgba(0,0,0,.08)` ✓ / `0 0 20px color` (색 후광) ✗ / `4px 4px 0 #000` (네오브루탈 아닌데 쓰면 ✗).
- **테두리 or 그림자 하나만.** 1px 선 + 넓은 그림자 = 유령 카드.
- **모서리:** 카드 12~16px. 알약 모양(999px)은 작은 버튼·태그에만.
- **이모지를 아이콘 대신 쓰지 않는다.** 체크·별·화살표는 SVG 인라인(`template.html`에 포함). 신뢰 배지에 🏆 같은 거 넣지 말 것.
- **브라우저 기본 요소도 디자인:** `::selection` 색, 포커스 링, 링크 밑줄 간격(`text-underline-offset`). 이거 안 하면 "조립한 티"가 난다.
- **줄무늬·격자 배경** (`repeating-linear-gradient`)은 실제 캔버스·설계도 느낌이 세계관일 때만. 플레이스홀더용은 OK.
- **AI 느낌 삽화(스케치풍 SVG, 그레인 노이즈)** 금지. 실사진 또는 없음.

## 6. 모션 — 기본으로 2곳, 그 이상 금지

사용자가 요청하지 않아도 **템플릿에 들어있는 2곳은 그대로 둔다.** 더 추가하지 않는다.

| # | 어디 | 뭐가 | 왜 거기 |
|---|---|---|---|
| ① | 1번 첫 화면 | 제목 → 보조문구 → 이미지가 0.1초 간격으로 살짝 올라오며 등장. 페이지 열 때 한 번 | 첫 3초 시선을 붙잡는 자리. 한 번만 움직이니 읽기를 방해하지 않는다 |
| ② | 6번 핵심 숫자(`.big`) | 스크롤해서 보이면 0에서 목표 숫자까지 0.9초 카운트업. 한 번만 | 숫자가 "움직이면" 기억에 남는다. 증거 섹션의 설득력이 올라간다 |

- 6번 증거 섹션이 없으면 ②는 자연히 없어진다. 대신 2번 신뢰 배지 숫자 하나에 `class="big"` 대신 `data-count`를 옮겨 붙이지 **않는다** — 배지 3개가 동시에 돌면 산만하다. 그냥 ①만 남긴다.
- 구매 버튼 펄스, 섹션마다 fade-in, 흔들리는 아이콘, 자동 슬라이드 — 전부 금지. impeccable 원칙: "한 번 연출된 순간 하나, 모든 섹션에 같은 등장 효과 반복은 없는 것보다 나쁘다."
- 이징은 `cubic-bezier(.16,1,.3,1)`(빠르게 시작해서 부드럽게 멈춤). 0.7~0.9초. 더 길면 답답하다.
- `prefers-reduced-motion` 켜진 기기에선 둘 다 꺼진다(템플릿에 포함).
- **플랫폼 한계:** 쿠팡·스마트스토어는 이미지로 올리니 모션이 사라진다. 자사몰(카페24 HTML)·미리보기·인스타 영상에서만 보인다. 사용자가 "움직이는 상세페이지"를 원하면 `upload.md`의 GIF/영상 변환 안내를 따른다 (스마트스토어는 GIF 허용, 쿠팡은 영상 기능).

## 7. 카피(UX 문구)

- CTA 버튼과 판매가는 기본적으로 넣지 않는다 (둘 다 사용자가 요구할 때만 — 모든 카테고리). 옵션 구성표(추가금만)는 SKILL.md "가격" 조건일 때 11번에. 마무리는 욕구 장면 문구 한 줄 — "사라/구매" 같은 직접 명령 금지. 버튼을 넣게 되면 행동을 이름 짓는다: "지금 구매하기" ✓ / "확인" ✗
- `copywriting.md` 규칙이 우선. 여기선 디자인과 맞물리는 것만: 제목은 15자 안팎, 2줄 넘기지 않는다.

## 8. 만든 뒤 점검 (한 번에, 한 번만)

impeccable 원칙: **무한 자가 검수 금지.** 다 만들고 → 한 번 전체 점검 → 발견한 것 한꺼번에 수정 → 한 번 더 확인 → 끝. 세 번째 루프 돌지 않는다.

점검 항목 (브라우저 도구 있으면 폰 폭 390px + 데스크톱 860px 캡처 한 번에):
- [ ] 첫 화면 3초: 상품·한 줄·버튼(또는 배지)이 스크롤 없이 보이나
- [ ] squint test: 주인공 → 두 번째 → 그룹 순서가 보이나
- [ ] 본문·설명·표 내용 16px 미만 없음, 보조 글자(각주·캡션·태그·브랜드바·표 머리) 12px 미만 없음(430폭), 대비 4.5:1
- [ ] 제목 단어 중간 끊김 없음, 2줄 초과 없음
- [ ] 강조색이 버튼·숫자·체크 외에 새지 않았나
- [ ] 이미지 깨짐·비율 틀어짐·placeholder 남은 곳 (의도한 것 외)
- [ ] 섹션 여백이 리듬 있게 (제목 위>아래, 섹션 간 > 요소 간)
- [ ] 구분선+키워드 바 합쳐 최소 3곳·최대 5곳, 풀블리드가 그리드·콜라주에 잘못 걸리지 않았나
- [ ] (버튼을 넣었다면) hover·focus 상태 있음, 높이 48px↑
- [ ] 판매가가 들어가지 않았나 (기본 미표기 — 사용자 요청 시에만). 옵션 구성표가 있으면 추가금이 사용자가 준 값과 일치하고 쿠팡용 파일엔 없나. 판매가를 넣었다면 처음 보이는 값이 총액인가
- [ ] 실제 문구 길이로 깨지는 곳 없음
- [ ] 사진마다 캡션 표기가 맞나 — 실물은 `.cap` "실물 촬영", AI는 `.cap.ai` "연출 이미지(AI 활용)"
- [ ] (스마트스토어) 3번 섹션이 앞 3,000px 안에서 시작하나 — `export_page.py` 보고서로 확인
- [ ] 사진 장수에 맞는 변형(`.c2`~`.c4`)을 썼나, 누끼를 cover 자리에 넣었으면 `.contain`, 머리·상품이 잘렸으면 `.pos-top` 등

점검에서 "별로"라고 느껴지는데 항목으로 못 잡겠으면 거의 항상 셋 중 하나다: **여백이 균일해서 리듬이 없거나, 강조색이 너무 많거나, 제목과 본문 크기 차이가 작거나.**

## 9. 템플릿별 디자인 규칙 (2026-11-21)

1~8항은 네 템플릿 공통 바닥(대비 4.5:1, 본문 16px↑·보조 12px↑, `cqw` 비례, 여백 리듬, 모션 2곳, 각주·연출 표기, 금지 패턴)이다. 그 위에서 **"무엇으로 설득하느냐"가 다르니 화면 언어도 달라야 한다.** 템플릿을 골랐으면 그 열만 따른다. 다른 열의 장치를 섞으면 템플릿들이 다시 하나로 뭉개진다.

| | 연출형 `template.html` | 정보설득형 `template-spec.html` | 매거진형 `template-magazine.html` | 소상공인 실사형 `template-maker.html` |
|---|---|---|---|---|
| 무엇으로 설득 | 장면·분위기 ("갖고 싶다") | 근거·비교 ("따져보니 맞다") | 취향·브랜드 ("나랑 맞는 곳이다") | 사람·기록 ("진짜로 하는 집이다") |

  |---|---|---|
  | `.duo` 두 톤 표지 | s-01 기본. 11번 마무리에 선택(`.duo.low`) | 띠 색 = 강조색, 띠 위 글자 = 강조색 짝 글자. 페이지당 2곳까지. 띠 색이 상품 색과 부딪히면 껍데기만 지우고 원래 표지로 |
  | `.arch` 아치 틀 | 표지 사진(기본), 3번 `.offset` | 세로 사진만. food·interior·tech 프리셋은 CSS가 둥근 모서리로 자동 전환. book 프리셋엔 쓰지 않는다 |
  | `.round` 둥근 모서리 | 5번 `.look.r`(기본) · 11번 `.duo` 사진 | `.look`에 붙이면 페이지 끝 쪽은 각지고 안쪽만 둥글다 |
  | `.oval` 타원·원 | 3번 `.offset` · 5번 `.closeups` | 기본은 꺼 둠. 틀 3곳 한도 안에서 |
  | `.pill` 알약 | 표지 `.duo-head` | 사진으로 안 보이는 사실 하나(색 수·구성·제작지). 1~2개. 가격·할인·"BEST" 금지 |
  | `.en` 영문 부제 | 표지 h1 바로 아래 | 상품명 영문 표기 그대로. 새 주장 금지. 없으면 삭제 |
  | `.tags` 키워드 | 표지 `.duo-head` 왼쪽 | 3항 예외 참고. 구체적인 말 2~3개, 빈말이면 삭제 |
  - 모양 틀(`.arch .round .oval`)은 **페이지에 2~3곳(표지 포함)**. 전부 둥글게 만들면 연출형과 구분이 없어진다 — 매거진형의 바탕은 여전히 종이와 여백이다.
  - 대비: 띠 위 글자는 테마마다 4.5:1 이상으로 맞춰 두었다(clean 5.8 · warm 5.2 · luxe 8.3 · fashion 18.6). pop·toy·baby·pet처럼 강조색이 밝으면 띠를 22% 어둡게 자동 보정(4.9~6.4:1). 새 프리셋·`data-gift`·`data-sale`로 강조색을 바꾸면 `--accent`/`--accent-fg` 대비를 먼저 계산한다.
- **선택 블록**(옵션 구성표·창업자 편지·포지셔닝 지도·옵션 카드·리뷰 캡처)은 네 템플릿에 각자 결로 들어 있다. 같은 블록이라도 그 템플릿 CSS를 쓴다 — 다른 템플릿 파일에서 복사해 오지 않는다.
- 사용자가 "중간 느낌"을 원하면 템플릿을 섞지 말고 **하나를 고른 뒤 테마·폰트만** 바꾼다(예: 정보설득형 + `data-theme="warm"`).

## impeccable 연동 (설치돼 있을 때)

사용자 환경에 `impeccable` 스킬(v4 이상, `~/.claude/skills/impeccable/`)이 있으면 위 8항 체크리스트 대신 이렇게 한다. 2026-11-20 v4.10 기준으로 맞춤.

1. **마감 패스:** HTML 완성 후 Skill 도구로 `impeccable`을 부르고 인자는 `polish <2_상세페이지.html 절대경로>`. 부를 때 아래 "고정 조건"을 같이 넘긴다 — 안 넘기면 impeccable이 Persuade 모드 기본값대로 구매 버튼을 달거나 섹션 구조를 바꾼다.
   > 고정 조건: Persuade 모드 상품 상세페이지. 이미지로 캡처해 스마트스토어·쿠팡에 올린다. 구매 액션은 플랫폼 구매 버튼이 맡으므로 CTA 버튼·판매가를 넣지 않는다(옵션 구성표 `.optable`이 있으면 그대로 둔다). `s-01`~`s-12` 섹션 순서·클래스, 문구, 사실 주장, 각주(`.fn`)·"연출 이미지"(`.cap`) 표기는 바꾸지 않는다. 글자 크기는 `cqw` 비례 유지, 본문·설명 16px 미만 금지(각주·캡션·태그·브랜드바·표 머리는 12px 이상). `<!-- PAGE-BODY:START -->`·`<!-- PAGE-BODY:END -->` 표지 주석은 지우지 않는다. 인라인 `style=`로 글자 속성 넣지 않는다(몰 삽입 변환에서 진다).
2. **셋업:** impeccable은 처음에 `scripts/impeccable context --target <파일>`을 한 번 돌린다. 이제 자체 실행 파일이라 **node가 필요 없다**(Windows bash가 아니면 `impeccable.cmd`). 실행이 막히면 다시 시도하지 말고 `reference/craft-floor.md`·`polish.md`·`mode-persuade.md`만 읽어 규칙으로 적용한다.
3. **렌더 확인:** 브라우저 도구 대신 `scripts/impeccable shot <html>`이 데스크톱·모바일을 한 번에 찍는다. 기계적 점검은 `scripts/impeccable detect --json <html>` 한 번. 둘 다 "한 번 보고 → 한꺼번에 고치고 → 한 번 확인" 안에서만 쓴다.
4. **피드백별 명령:** "밋밋하다" → `bolder`, "너무 요란하다" → `quieter`, 글자만 → `typeset`, 여백·위계만 → `layout`, 문구가 어색 → `clarify`(사실·주장은 바꾸지 말라고 같이 말한다).
5. 이 스킬의 템플릿·문서와 impeccable이 부딪히면 아래 표대로. 표에 없으면 **impeccable이 이긴다** — 템플릿은 출발점이지 규칙이 아니다.
